# AfterSeoul 모바일 게임 진행도 점검

최초 점검 기준: 2026-09-26, 커밋 `15977ce`. 아래는 수정 전 소스·데이터·설정과 실행 결과를 기록한 기준 보고서다. 이후 구현 내용과 검증은 [모바일 안정성·캐릭터 성장 작업](MOBILE_READINESS_2026_09_26.md)에 정리했다.

## 현재 단계

**핵심 플레이가 구현된 내부 알파. 외부 베타에 앞서 초반 안내, 저장 복구, 실기기 검증을 마쳐야 한다.**

공장만 있는 초기 프로토타입은 이미 벗어났다. 직접 탐색·전투·파밍·생환, 동료 고용·장비·파견, 공장 생산·자동화, 창고·거래·의뢰가 존재한다. 다만 기능 존재 여부와 모바일 제품의 완성도는 구분해야 한다. 테스트 통과만으로 조작감, 재접속 의욕, 장기 경제, 실기기 안정성이 확인되는 것은 아니다. 고정된 출시 범위가 없어 전체 진행률을 임의의 백분율로 산정하지 않았다.

| 분야 | 확인된 구현 | 현재 판단 |
|---|---|---|
| 직접 탐색 | 8개 지역, 경로 선택, 6~10개 사건, 중간 탈출, 전투·회피·엄폐, 탄약·소모품, 지역별 물자 | 핵심 플레이 구현. 인간 플레이 기준 난이도·판 길이 검증 필요 |

| 퀘스트·성장 | 선택 고용주 3명, 일일 의뢰 22종, 첫 의뢰·지역 소개·일부 후속 의뢰, 재료 시설·장비 교환 | 초반 목표는 있음. 중후반 목표와 표시되는 성장 지표 보완 필요 |
| 모바일 표현 | 세로 화면, 기본 안전영역, 큰 터치 버튼, 스크롤, 5개 언어, 일러스트·오디오·설정 | 기본 구현. 일부 팝업·뒤로 가기·앱 전환 검증 부족 |

| PC 연동 | 모바일 클라이언트, 본편 수령 코드, Cloud Code 우편함과 검증 정책 | 코드 존재, 현재 서비스 비활성. 실제 배송 미검증 |
| 수익화·출시 | 결제·광고 인터페이스와 개발용 테스트, Android 개발 APK | 실제 SDK·배포 설정·운영 계측 미완 |

데이터 정의는 아이템 462종, 파견 지역 8개, 전리품 표 7개, 제작 레시피 9개, 파견 사건 7개, 고용주 3명, 상점 품목 58종, 일일 의뢰 22종이다. 아이템 정의 수가 실제 획득 가능한 콘텐츠 수를 뜻하지는 않는다. 총기 생산 25종은 별도 생산 의뢰이며, 완성 총기를 창고에 넣는 제작과 구분된다.

## 이번에 확인한 문제와 작업 순서

### P0 — 외부 테스트 전에 처리

1. **초도 파견 이후 안내가 잠긴 명동을 권한다 — 실행으로 재현.**
   - 무료 초도 파견 완료 후 장비·자금을 준비하면 `GrowthGuide`는 명동 일반 파견을 제안한다. 그러나 현재 일반 파견의 지역 해금은 직접 탐색 생환 경로를 따르고, 명동은 주요 6개 지역을 거친 뒤 열린다.
   - 첫 용산 생환과 초도 파견을 완료한 상태에서도 고용주 3명 모두 `Depart / MYEONGDONG`을 제안했고, 실제 파견 생성은 거절됐다. 전체 게임이 막히는 것은 아니지만 초반 안내가 실행할 수 없는 행동을 권한다.
   - 근거: [GrowthGuide.cs:82](../Assets/Game/Core/GrowthGuide.cs#L82), [HomeScreen.cs:264](../Assets/Unity/UI/Screens/HomeScreen.cs#L264), [MapUnlock.cs:33](../Assets/Game/Expedition/MapUnlock.cs#L33), [ExplorationSystem.cs:24](../Assets/Game/Exploration/ExplorationSystem.cs#L24).
   - 작업: 현재 열려 있고 해당 팀이 출발할 수 있는 지역에서 다음 파견 목표·예산을 계산하고, 안내 문구와 연결 화면을 함께 갱신한다.
   - 완료 조건: 고용주 3명에서 첫 탐색 → 첫 고용 → 무료 파견 → 일반 파견이 안내대로 이어지고, 제안한 파견을 실제로 생성할 수 있다.

2. **저장 손상 시 백업 복원이 없다 — 코드로 확인.**
   - 저장할 때 `save.json.bak`를 만들지만, 기본 저장을 읽지 못하면 `.corrupt`로 옮기고 새 게임을 만든다. 기존 백업을 읽는 경로는 없다. 부팅부는 이를 로그 경고로만 남긴다.
   - 근거: [SaveService.cs:38](../Assets/Game/Core/SaveService.cs#L38), [SaveService.cs:157](../Assets/Game/Core/SaveService.cs#L157), [Bootstrap.cs:84](../Assets/Unity/Bootstrap.cs#L84).
   - 작업: 유효한 백업 복원, 손상 파일 보존, 복구 결과 안내, 복구 불가능할 때의 재시작 선택을 마련한다. 기기 변경·재설치 시 진행 복구 정책도 정한다. 우편함용 Cloud Save와 전체 진행 백업은 별도 문제다.
   - 완료 조건: 정상 저장/기본 저장 손상/백업까지 손상/저장 공간 부족/강제 종료 각각에서 진행 보존 또는 명확한 복구 안내가 확인된다.

3. **검증 도구가 현재 해금 규칙을 따라가지 못한다 — 실행으로 확인.**
   - `Tools/check_data.py`는 지역 조건에 숫자 `value`가 있다고 가정하여 현재의 `explorationRoute`에서 `KeyError: 'value'`로 종료된다. 게임은 이 조건을 지원하므로 이 실패를 게임 데이터 전체의 오류로 해석하면 안 된다.
   - `Run-GrowthVerification.ps1`도 `wait on active trip`에서 실패한다. 명동 출발이 거절돼 실제 파견이 생기지 않은 것이 원인이다.
   - 근거: [check_data.py:302](../Tools/check_data.py#L302), [GrowthVerification.cs:68](../Tools/GrowthVerification.cs#L68).
   - 작업: 검사 도구에 실제 생환 해금 순서를 반영하고, 성장 안내가 제안한 행동의 실행 가능성을 회귀 검사한다. 누락된 숫자를 임의로 채워 검사만 통과시키면 안 된다.
   - 완료 조건: 전체 데이터 검사와 초반 성장 검사가 현재 규칙에서 끝까지 실행된다.

### P1 — 모바일 완성도와 반복 플레이

4. **모바일 조작·팝업 처리를 통일한다.**
   - 캐릭터 프로필·언어·설정·일부 생산 팝업은 전체 Canvas 아래 생성되며 별도의 안전영역 처리가 없다. 기본 패널의 고정 여백만으로 모든 노치·제스처 영역을 피할 수 있는지는 미검증이다.
   - Android 시스템 뒤로 가기로 팝업·하위 화면을 닫는 입력 처리를 소스에서 찾지 못했다. 공장 홀드 조작은 앱 전환 중 손 떼기 이벤트가 누락될 때 상태가 남을 가능성이 있다. 후자는 실기기 재현 전 위험이다.
   - 근거: [AppShell.cs:498](../Assets/Unity/UI/AppShell.cs#L498), [AppShell.cs:640](../Assets/Unity/UI/AppShell.cs#L640), [Ui.cs:409](../Assets/Unity/UI/Ui.cs#L409), [HoldGame.cs:45](../Assets/Unity/UI/Minigame/HoldGame.cs#L45), [FactoryScreen.cs:834](../Assets/Unity/UI/Screens/FactoryScreen.cs#L834).
   - 작업: 팝업 안전영역 기준을 통일하고, 뒤로 가기 순서를 정의한다. 작은 화면·긴 화면·노치 기기에서 키보드, 연속 터치, 누른 채 앱 전환, 알림 거부, 잠금 후 복귀를 확인한다.
   - 기존 캡처에서 출발 준비에는 장비 7칸·물자·시설 목표·대여 설명이 함께 보인다. 권장 준비를 기본으로 유지하고 세부 설명은 필요할 때 확인하도록 줄이는 편이 좋다. 가방 정리는 장착 장비 대비 효과와 현재 목표에 필요한 물자를 우선 보여준다. 이는 화면 검토에 따른 사용성 제안이며 사용자 관찰 결과는 아니다.

5. **캐릭터 성장 표시와 실제 보상을 맞춘다.**
   - `CharacterLevel=1`, `CharacterExp=0`이 프로필·홈·장비·귀환 화면에 표시된다. 현재 게임 코드에는 이 경험치를 지급하거나 캐릭터 레벨을 올리는 경로가 없다. 별도의 기지 레벨 `Player.Level/Exp`는 동작한다.
   - 근거: [GameSave.cs:85](../Assets/Game/Core/GameSave.cs#L85), [CharacterProfileUi.cs:15](../Assets/Unity/UI/CharacterProfileUi.cs#L15), [ExplorationSystem.cs:571](../Assets/Game/Exploration/ExplorationSystem.cs#L571).
   - 작업: 캐릭터 성장의 의미를 정해 보상을 연결하거나, 성장 설계가 확정될 때까지 변하지 않는 경험치·레벨 노출을 정리한다. 단순 전투력 증가를 반드시 추가해야 한다는 뜻은 아니다.
   - 완료 조건: 플레이어가 탐색을 마쳤을 때 무엇이 성장했고 다음 목표가 무엇인지 설명할 수 있다.

6. **첫날·일주일·한 달의 성장 속도를 검증한다.**
   - 직접 탐색 시설은 3종 각 2단계, 장비 교환은 7종이다. 지역 후속 의뢰는 구로·한강·남산에 각 2단계가 있다. 일반 일일 의뢰의 `chainNextId`를 사용하는 연속 의뢰는 아직 없다. 따라서 모든 후속 의뢰가 미구현이라고 볼 수는 없다.
   - 근거: [RaidProgression.cs:26](../Assets/Game/Exploration/RaidProgression.cs#L26), [RegionalExplorationQuest.cs:90](../Assets/Game/Core/RegionalExplorationQuest.cs#L90), [SessionAndDataTests.cs:751](../Assets/Tests/EditMode/SessionAndDataTests.cs#L751).
   - 현재 홈과 지역 해금은 직접 탐색을 중심에 둔다. 이 흐름을 기준으로 첫 탐색 → 회수품 활용 → 동료 고용/공장 투자 → 다음 탐색 준비의 연결을 정리한다. 이전 방치형 문서의 순서를 그대로 목표로 삼으면 구현과 다시 어긋난다.
   - 작업: 첫 30분의 설명 없는 플레이를 관찰하고, 1/7/30일에 도달할 목표·자금·재료 소비처를 정한다. 직접 탐색·공장·파견의 시간당 보상, 상위 지역의 선택 이유, 창고 포화, 실패 후 재시도 비용을 한 경제에서 비교한다.
   - 파견은 현재 20~180분이며 원 GDD의 3/6/12시간 접속 간격과 차이가 있다. 긴 파견을 무조건 추가하기보다 목표 접속 패턴에서 수령·재파견이 얼마나 번거로운지 먼저 측정한다.
   - 최신 자동 용산 생환 검사는 100개 시드 모두 생환, 순회수가치 중앙값 59,640원을 기록했다. 정해진 회피·엄폐 정책의 결과이므로 실제 초보 생존율이나 장기 재미를 뜻하지 않는다.
   - 완료 조건: 초반 플레이 관찰 기록과 장기 경제 결과로 첫 업그레이드 시점, 다음 접속 목표, 주요 재료 소비처를 설명할 수 있다.

7. **기기 성능과 운영 관측을 마련한다.**
   - 실제 저사양 기기의 시작 시간·메모리·프레임·발열·배터리 측정 기록은 확인하지 못했다. 화면 계층을 매 프레임 검색하는 경로가 있고 이미지/폰트를 상주 캐시하므로 측정 우선 대상이다. 성능 문제가 발생했다고 단정한 것은 아니다.
   - 근거: [AppShell.cs:258](../Assets/Unity/UI/AppShell.cs#L258), [ItemArtwork.cs:20](../Assets/Unity/UI/ItemArtwork.cs#L20).
   - 작업: 지원할 낮은 사양의 폰과 보통 사양의 폰에서 20~30분 연속 플레이를 측정한다. 크래시·저장 실패·시작/복귀 실패와 튜토리얼 이탈·첫 생환·첫 고용·재접속을 관찰할 최소 이벤트를 정의한다. 현재 별도 운영 계측 호출은 소스에서 확인하지 못했다.

### P2 — 출시 범위에 따라 진행

8. **PC 배송을 실제 서비스로 검증한다.**
   - 양쪽 코드와 서버 구현은 존재하지만 `MobileMailConfig.enabled=false`이고 모바일 Unity 프로젝트 연결도 비어 있다. 알파 계정의 서버 우편함은 수동 초기화가 필요하며 계정당 누적 1,000건 제한이 있다.
   - 근거: [MobileMailConfig.json](../Assets/Resources/MobileMailConfig.json), 본편 `D:/devSource/EscapeFromSeoul/docs/mobile-link/SETUP.md`.
   - 작업: 테스트 서비스 설정·배포·계정 준비 후 모바일 발송 → PC 수령 → 재시작까지 확인한다. 응답 유실·중복 요청·동시 발송·계정 전환·저장 실패도 검증한다. 공개 가입용 안전 초기화와 장기 거래 기록 보관 정책이 필요하다.
   - 오프라인 재고 획득의 진위와 클라이언트 역할 증명은 현 구조의 제한이다. 출시 시 허용할 보호 수준을 정한다.
   - 모바일 단독 베타를 먼저 연다면 연동 비활성을 유지할 수 있다. PC 연동을 출시 기능으로 홍보한다면 이 검증은 출시 전 필수다.

9. **수익화 연결과 배포 절차를 완성한다.**
   - 기기 빌드는 `NullStore`를 사용한다. 실제 결제·광고 SDK는 연결되지 않았다. 지원계약·보상 규칙과 개발용 가짜 상점은 별도로 존재한다.
   - 근거: [IStore.cs:59](../Assets/Game/Core/IStore.cs#L59), [Bootstrap.cs:74](../Assets/Unity/Bootstrap.cs#L74), [AlphaBuild.cs:10](../Assets/Unity/Editor/AlphaBuild.cs#L10).
   - 작업: 수익화를 넣는 시점에 구매/광고 완료·취소·중복 콜백·구매 복원·영수증 처리를 검증한다. 무과금 내부 테스트를 위해 먼저 연결할 필요는 없다.
