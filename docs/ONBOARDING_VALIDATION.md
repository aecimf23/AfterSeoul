# 첫 30분 백그라운드 검증 — 2026-09-15

## 결론

코어 정산·저장 흐름에서는 이번 검증의 실패가 없었다. 그러나 느린 조작에서는 첫 파견 복귀가 30분 밖으로 밀리고, 기본 장비의 첫 파견에서 인원 손실 사례가 나왔다. 다음 우선순위는 첫 복귀까지의 대기와 초반 위험을 조정하는 것이다.

**실제 30분 손 플레이가 아니다.** 실제 게임 C# 소스와 실제 JSON 데이터를 컴파일해 가상 시간을 진행한 자동 검증이다. Unity나 새 게임 창을 띄우지 않았고, 마우스·키보드·OS 시계를 사용/변경하지 않았다. 시뮬레이터는 낮은 CPU 우선순위로 실행했다. 기존 사용자 저장과 PlayerPrefs를 읽거나 변경하지 않았다.

## 검증 조건

- 고용주 3명 × 조작 정책 4종 × 시작 시각 변형 12개 = **144회**.
- 시작 자금 0, 실제 시장 후보 중 가장 싼 1명 고용. 임의 자금/아이템/해금 지급 없음.
- 시작 60초는 읽기·선택 시간으로 가정.
- 수동 제작은 폐자재 분류 3단계만 반복한다. 단계 사이 시간을 15/30/60초로 가정하며, 단계 점수는 각각 0.85/0.60/0.30으로 고정한다.
- 무료 5분 제작 큐를 완료 때마다 다시 등록한다. 큐 전용 정책 역시 사람이 재등록하는 상황을 가정하며, 앱을 완전히 꺼두는 플레이가 아니다.
- 완납 가능한 의뢰는 납품한다. 폐자재로 충족 가능한 미완료 의뢰의 요구량은 보존하고 나머지 폐자재를 판매한다.
- 첫 고용 시 지급 무기를 벗겼다 다시 장착한다. 비용을 확보하면 명동에 단독 1회 파견한다.
- 두 번째 인원/파견, 작업대 업그레이드, 복잡한 의뢰 전용 제작, 치료·구조 전략은 30분 정책에 포함하지 않는다. 따라서 잔액은 최적 성장 전략의 잔액이 아니다.
- 판정·화면 입력을 실제로 조작한 것이 아니라 GameSession 공개 메서드에 점수를 공급했다. 손의 난이도·재미·모바일 터치 검증을 대체하지 않는다.

시작 시각 변형은 시장 인원·의뢰의 변화를 만든다. **파견 난수 144개를 독립적으로 추출한 실험이 아니다.** 신규 RngCounter가 동일하고 작업 순서가 비슷하면 같은 파견 seed가 재사용되므로 이 실험으로 사고 확률을 추정하면 안 된다.

### 의뢰

황 상사의 금속 의뢰가 배정된 시작 조건에서는 실제 재료를 소비한 납품과 중복 납품 거절을 확인했다. 다른 고용주는 이번 폐자재 중심 정책에서 납품이 없었다. **이 사실만으로 해당 고용주의 의뢰가 불가능하거나 버그라고 결론 내릴 수 없다.** 지역 전리품 수집/의뢰 전용 제작 정책은 별도 검증해야 한다. 파견 전리품을 납품하는 전체 경로를 모든 고용주에서 완료했다는 의미도 아니다.

### 첫 파견 위험 사례

보통 정책에서는 부상 및 인원 상실 사례가 발생했다. 예: 시작 변형 0, 명동 단독, 지급 무기 MEL01, 파견 seed 2027808452는 결과 저장에 Injured로 기록된다. 손실 발생 여부를 재현한 것이며 확률 측정은 아니다. 첫 복귀의 감정적 경험을 실제로 평가한 것도 아니다.

## 다음 개선 제안 — 아직 게임 수치 변경 없음

1. **첫 복귀를 앞당기는 튜토리얼 파견 검토.** 현재 명동의 20분 대기에 고용 준비 시간이 추가된다. 첫 1회 짧은 파견으로 복귀·획득·납품을 먼저 경험하게 하는 방향을 권한다.
2. **첫 파견의 손실 보호 검토.** 지급 무기로 단독 출발한 초보자에게 부상·상실이 가능하다. 첫 1회 보호 또는 장비·팀 안전성 안내를 강화할지 결정한다.
3. **손 플레이와 큐의 속도 차이 재평가.** 정책 간 수입 차이가 크다. 단순 반복을 장려하는지, 업그레이드·보조 인력 안내가 적절히 연결되는지 실제 플레이로 확인한다.
4. **고용주별 의뢰 목표를 따르는 자동 정책 추가.** 이번 결과는 폐자재 중심 한 가지 전략이다. 다른 고용주가 30분 내 첫 납품까지 갈 수 있는지는 추가 검증 범위다.

이번 작업은 검증 도구와 보고서 추가다. 밸런스 변경, 저장 초기화, 출시용 서비스 호출은 하지 않았다.
