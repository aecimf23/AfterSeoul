## 1. 프로젝트 개요

AFTER SEOUL 은 PC 게임 `ESCAPE FROM SEOUL` 과 동일한 세계관·지역을 공유하는 모바일 게임이다.

플레이어는 본편에 등장하는 주요 NPC 중 한 명의 밑에서 일하는 **하위 팀장**으로 시작한다.
초기에는 혼자 공장에서 단순 작업으로 돈을 벌고, 성장하면서 스캐브 성격의 부하 직원을 고용해 서울·수도권 지역으로 파견하여 물자와 장비를 회수한다.

회수품의 용도는 셋:

1. **판매** — 모바일 운영자금 확보
2. **내부 사용** — 스캐브 장비 지급 / 제작 재료 / NPC 납품
3. **본편 발송** — PC 하이드아웃 우편함으로 전송

**모바일 게임은 독립적으로 완결된 무료 게임이어야 한다.** PC 본편 소유 여부는 플레이에 영향을 주지 않는다.

## 2. 핵심 판타지와 성장 축

> 나는 처음엔 이름 없는 말단 작업자였지만, 직접 돈을 벌고 사람을 고용하면서 점점 서울 곳곳에 회수팀을 보내는 현장 책임자가 된다.

```
혼자 일하는 작업자 → 하위 팀장 → 첫 스캐브 고용 → 소규모 회수팀
→ 다중 팀 운용 → 공장 생산 자동화 → 서울 전역 파견 → 대규모 회수조직 관리자
```

**레벨 숫자가 아니라 "플레이어가 실제로 하는 조작"이 바뀌어야 한다.**
초반: 직접 탭해서 부품을 만든다. 후반: 생산 라인과 인원 배치를 결정한다.

### 성장 단계별 조작 비중 (설계 목표)

| 단계 | 직접 클리커 | 관리/배치 | 의사결정 |
|---|---|---|---|
| 1~2일차 | 70% | 20% | 10% |
| 1주차 | 40% | 40% | 20% |
| 1개월차 | 10% | 50% | 40% |

▶ 0.2 변경: 성장 단계별 조작 비중 표를 추가. 이 비율이 깨지면 설계가 틀어진 것으로 판단한다.

## 3. 핵심 게임 루프

```
접속 → 공장 생산물 수령 → NPC 일일 의뢰 확인 → 작업/제작
→ 스캐브 고용·장비 세팅 → 지역 탐색 파견 → (시간 경과) → 스캐브 복귀
→ 회수품 획득 → [판매 | 내부 사용 | 본편 발송] → 조직 성장 → 상위 지역·의뢰 개방
```

짧게 접속해 처리하고 나가는 패턴이 목표다.

| 시점 | 소요 | 할 일 |
|---|---|---|
| 출근 전 | 2~4분 | 생산품 회수, 복귀 스캐브 결과 확인, 일일 의뢰 수령, 신규 파견, 제작 큐 설정 |
| 점심 | 1~2분 | 제작 완료품 수령, 단기 탐색 결과 확인, 재파견 |
| 퇴근 | 4~8분 | 장기 탐색 결과, 창고 정리, NPC 납품, 본편 발송 |

**설계 규칙: 한 번의 접속으로 처리해야 할 일이 10분을 넘으면 안 된다.**
파견 시간 설계는 이 3회 접속 리듬(대략 3시간 / 6시간 / 12시간 간격)을 기준으로 맞춘다.

▶ 0.2 변경: 접속 1회당 상한 10분 규칙과 3회 접속 리듬을 명문화.

## 4. 고용주 NPC 선택

게임 시작 시 본편 상인 NPC 중 한 명을 상관으로 선택한다. 후보는 본편에 실존하는 8명:

| Id | 한글명 | 성향 | 모바일 특화 |
|---|---|---|---|
| `HWANG` | 황 상사 | 군수 | 총기/탄약/군용 부품 의뢰, 장비 제작 보너스 |
| `DR_CHOI` | 보건의 최씨 | 의료 | 의약품 의뢰, 스캐브 부상 회복 속도 |
| `BROKER` | 장물아비 | 밀매 | 판매가 보너스, 귀중품 의뢰 |
| `YONGSAN_KIM` | 용산 킴 | 전자 | 전자부품 의뢰, 용산 탐색 보너스 |
| `DOKKAEBI` | 도깨비 | 정보 | 탐색 정보 정밀도, 히든 루트 |
| `US_LIAISON` | 미군 연락책 | 군용 | 미군 물자, 용산 미군기지 |
| `DONGDAEMUN_CHOI` | 동대문 최씨 | 잡화 | 식량/잡화, 창고 효율 |
| `WILDMAN` | 와일드맨 | 야전 | 고위험 지역, 생존 특화 |

**MVP 에서는 `HWANG` 1명만 구현한다.**

### 절대 규칙

NPC 선택으로 **지역이나 콘텐츠가 영구적으로 잠기면 안 된다.**
선택은 초반 30분~1주의 경험을 차별화할 뿐, 중후반에는 모든 지역·의뢰 풀에 접근 가능하다.
NPC 별 차이는 **해금 순서와 보너스 수치**로만 표현한다.

▶ 0.2 변경: NPC 후보를 본편 실제 `Trader` 8명으로 확정하고 id 를 명시.

## 5. 일일 의뢰 시스템

일일 의뢰는 **매일 접속할 이유**이자 **기존 시스템을 다시 작동시키는 장치**다.
새 콘텐츠를 추가하는 게 아니라, 공장·제작·탐색·판매·창고·장비를 다시 돌게 만드는 것이 목적이다.

### 의뢰 하나가 반드시 건드려야 하는 시스템

의뢰는 아래 중 **최소 2개**를 경유해야 채점된다. 창고에 이미 있는 물건을 내기만 하면 되는 의뢰는 나쁜 의뢰다.

`공장` `제작` `스캐브 탐색` `아이템 판매` `창고` `NPC 신뢰도` `장비 관리`

### 황 상사 예시

**초반**
> "지금 기지 보수에 필요한 볼트 5개만 구해와봐. 보수는 챙겨두지."
> 요구: 볼트(`JUNK03`) ×5 / 보상: **₩95,000**, 신뢰도 +3, 경험치

> ⚠ 0.1 에서 이 보상은 ₩8,000 이었다. 본편 실측 결과 볼트 단가가 **15,000원**이라
> 5개면 75,000원어치다. 8,000원에 넘기면 의뢰가 손해 보는 장치가 된다.
> 금액 체계 전반은 [DATA_SCHEMA.md §3-1](DATA_SCHEMA.md#3-1--본편-경제-스케일--기획서-수치-전면-재조정-필요) 참조.

**중반**
> "구로 쪽에서 의료품이 부족하다더군. 붕대 세 개하고 진통제 두 개만 챙겨."

**후반**
> "내가 알고 있는 PMC 녀석에게 임무를 줘야 하는데 AV-74M 한 정이 필요해. 어떻게 해서든 구해와."

해결 경로가 여러 개라는 점이 핵심이다:

- 탐색 중 완제품 회수
- 부품 회수 후 제작
- 고장 난 총기 회수 후 수리
- 다른 물자 판매 후 완제품 구매

**일일 의뢰는 체크리스트가 아니라 작은 경제·운영 퍼즐이다.**

### 난이도 성장

| 단계 | 예시 |
|---|---|
| 초기 | 볼트 ×5 / 천 조각 ×4 / 배터리 ×2 |
| 중반 | 진통제 ×2 / 전자부품 ×5 / 5.45mm 탄약 ×30 |
| 후반 | `WPN01`(AV-74M) 1정 / 특정 군용 장비 / 고급 전자부품 / 내구도 조건부 무기 |

### 연속 의뢰

일부 의뢰는 여러 날에 걸쳐 이어진다.

```
DAY 1  "AK 부품 몇 개만 구해와."
DAY 2  "어제 가져온 걸 확인했는데 가스 튜브가 하나 모자란다."
DAY 3  "조립은 끝났다. 테스트할 탄약 좀 가져와."
DAY 4  "좋아. 이 정도면 그 녀석한테 넘겨도 되겠군."
```

단순 반복 퀘스트를 세계관 서사로 바꾸는 장치. 본편 `Quest.PrerequisiteQuestId` / `NextQuestId` 체인 구조를 그대로 차용한다.
모바일 퀘스트 id 는 `DQ_` 접두사 (본편 `Q_` 와 분리).

▶ 0.2 변경: "최소 2개 시스템 경유" 채점 규칙 추가. 퀘스트 체인 구조를 본편 모델 차용으로 확정.

## 6. 공장 / 클리커

초기에는 플레이어가 직접 공장에서 일해 돈을 번다. **단순 연타는 쓰지 않는다.**

### 짧은 공정형 미니게임

```
재료 배치 → 조립 → 타이밍 입력 → 검수 → 완료
```

1회 작업 목표 시간: **5~15초**.

### 작업 종류

| 등급 | 예시 |
|---|---|
| 단순 | 볼트 가공, 금속부품 조립, 전선 정리, 포장 |
| 중급 | 전자부품 조립, 의료키트 제작, 탄창 정비, 총기부품 가공 |
| 고급 | 총기 수리, 소총 조립, 특수 장비 제작, 고급 전자장비 수리 |

### 성장 경로

```
수동 작업 → 작업대 개선 → 생산 효율 향상 → 보조 인력 고용 → 반자동 생산 → 자동 생산
```

### 품질 시스템

단순 성공/실패가 아니라 4단계: `실패` `보통` `양호` `우수`

품질이 영향을 주는 곳: 판매가격 / 제작 성공률 / NPC 의뢰 만족도(신뢰도 증가량)

**지나치게 복잡한 제작 시뮬레이션은 피한다.** 품질은 이 3곳에만 영향을 주고 더 늘리지 않는다.

## 7. 스캐브 시스템

### 고용과 운영비

스캐브는 **무료로 보내지 않는다.** 모든 탐색에 운영비가 발생한다.

```
구로 폐공단
파견시간   35분
인건비     ₩60,000
보급비     ₩25,000
─────────────────
총 파견비  ₩85,000
```

파견비 = 예상 회수 가치 × 0.55 (기대 마진 45%, 사고 확률 감안 시 실질 25~35%).

고급 스캐브일수록 높은 급여를 요구한다. **파견 결정 자체가 손익 판단이어야 한다.**

### 능력치 (MVP 는 3개만)

`탐색` `전투` `생존`

### 특성 예시

| 특성 | 효과 |
|---|---|
| 전자상가 출신 | `YONGSAN_MARKET` 탐색 보너스 |
| 겁쟁이 | 전투 발생 시 도주 확률 증가 (생존↑, 회수량↓) |
| 의무병 출신 | 부상 생존률 증가 |

### 장비 (0.3 개정)

6칸. **무기만 필수**이고 나머지 다섯은 비워도 파견할 수 있다.

| 칸 | 본편 스탯 | 효과 |
|---|---|---|
| `무기` | 등급 1~5 (가격) | **좋은 물건 습득률↑** — 없으면 파견 불가 |
| `헬멧` | `ArmorClass` 1~6 | 사망→실종→부상 한 단계 강등 |
| `방탄복` | `ArmorClass` 1~6 | 생존↑ (사고 확률↓) |
| `헤드셋` | `HearingRange` 12/15/18 | 좋은 물건 습득률↑ + 생존↑ |
| `리그` | 적재칸 6~12 | 회수 +1~2회 |
| `가방` | 적재칸 16~64 | 회수 +1~3회 |

사망·실종 시 장비 손실. **위험과 보상의 저울.**

▶ 0.2 → 0.3 변경 이유:
- 기존 6종(`총기` `방탄복` `가방` `의료품` `손전등` `특수도구`) 중 **의료품·특수도구는 본편에 슬롯이 없고**, 정작 본편에 있는 헬멧·리그가 빠져 있었다. 본편 `EquipmentSlot` 에 맞추면 아이템 58종을 그대로 쓸 수 있고 새로 만들 게 없다.
- **무기는 본편의 주무기·보조무기·근접무기를 한 칸으로 합쳤다.** 모바일에서는 교전을 직접 조작하지 않으니 셋을 갈라 봤자 선택이 아니라 칸 채우기가 된다. 합쳐두면 "단검 하나만 쥐여 보낸다"가 성립한다 — 싸게 파견은 되지만 좋은 물건은 못 가져온다. 근접무기는 값이 얼마든 전부 등급 1이다(크림슨 아이스픽 950,000원도 등급 1 — 그건 장비가 아니라 팔 물건이다).
- **무기 효과가 전투력이 아니라 습득률인 이유**: 이 게임에서 스캐브는 싸우러 가는 게 아니라 뒤지러 간다. 좋은 무기 = 그 자리를 더 오래 지킬 수 있다 = 눈에 띄는 것 아무거나 집어 나오지 않아도 된다.
- 의정부 서바이벌 모드 전용 장비(`UIJ_` 접두사 — 석궁·곡괭이·고철 헬멧 등)는 제외한다. 본편에서도 서울 경제권과 분리된 인벤토리를 쓴다.
- **내구도·수리는 넣지 않는다.** 본편은 수리할 때마다 최대치가 2%씩 영구로 깎이는 방식인데, 모바일에서 그것까지 관리시키면 화면이 하나 더 필요하다. "사망·실종 시 손실"만으로 저울은 성립한다.

### 애착 시스템

스캐브는 숫자 카드가 아니라 이름과 이력을 가진 사람이어야 한다.

```
김철수  LV.7
탐색 8  전투 5  생존 9
특성: 전자상가 출신, 겁쟁이
누적 파견 23회 · 회수 총액 ₩1,240,000
```

오래 살아남은 스캐브의 죽음·실종은 사건이 되어야 한다.
확장 후보: `"김철수의 무전 신호가 다시 포착되었습니다."` → 구조 임무 발생

▶ 0.2 변경: 스캐브 카드에 누적 이력(파견 횟수, 회수 총액)을 추가. 애착은 이름이 아니라 누적 기록에서 나온다.

## 8. 탐색 시스템

본편의 서울·수도권 지역을 그대로 세계관 자산으로 사용한다 ([전체 목록](MAINLINE_REFERENCE.md#2-지역-재활용-확정)).

탐색은 **비동기**다.

```
팀 설정 → 지역 선택 → 장비 설정 → 파견비 지급 → 탐색 시작

```


| Id | 한글명 | 본편 난이도 | 모바일 역할 |
|---|---|---|---|
| `MYEONGDONG` | 명동 | Easy | 튜토리얼 첫 파견. 저위험·저보상. 잡화/식량 |

1. **판매** — 운영자금

모바일 자금 용도: 스캐브 고용 / 급여 / 파견비 / 장비 구매 / 제작 / 공장 업그레이드 / 창고 확장

## 10. PC 본편 연동

상세 규격은 [LINK_CONTRACT.md](LINK_CONTRACT.md) 가 정본. 여기서는 원칙만.

### 구성

```
Unity Authentication + Code-Link + Unity Cloud Save
```

**자체 WAS / DB 서버는 운영하지 않는다.**
Cloud Save 는 전체 세이브 저장소가 아니라 **두 게임 사이의 우체통 + 최소 공유 상태**다.
각 게임의 전체 세이브는 로컬에 유지한다.

### 공유 상태 개념

```
SharedState
├─ MainGame   : 진행 상태 / 발견 지역 / 월드 플래그
├─ MobileGame : 필요 연동 상태 / 해금 상태
└─ TransferBox
   ├─ MOBILE_TO_PC
   └─ PC_TO_MOBILE
```

### 본편 우편함 연출

본편 실행 시:

```
하이드아웃에 도착한 우편이 있습니다!
```

플레이어는 하이드아웃으로 이동해 우편함/보급함 오브젝트와 상호작용한다.

```
발신 : 서울 회수팀 R-04

진통제 ×2
군용 배터리 ×1

[모두 수령]
```

**게임 외적인 "모바일 보상 수령" UI 가 아니라, 세계관 내부의 실제 배송 시스템처럼 보여야 한다.**

### 발송 밸런스 원칙

- 전송 기능은 **매우 강하게 제한**한다
- 양쪽 클라이언트에서 **각각 validation** 한다
- **PC 본편 밸런스 파괴 방지가 최우선**
- 유료 사용자라고 더 많이 보낼 수 없다 — 전송 한도는 무료/유료 동일

## 11. 수익화

### 철학

핵심 콘텐츠는 전부 무료로 플레이 가능해야 한다.
과금하지 않아서 **핵심 지역 접근 불가 / NPC 사용 불가 / 성장 불가** 가 되는 구조는 쓰지 않는다.

### 후보

**선택형 보상 광고** — 강제 광고 금지.

**월간 지원계약** (편의 기능 중심)
- 공장 자동작업 강화
- 오프라인 생산시간 증가
- 파견 예약 큐 증가
- 상세 탐색정보
- 모바일 창고 확장
- 광고 보상 기능 자동 적용

**작전 패스** — 게임 안정화 후 고려.

### 금지

강제 광고 · 고급 스캐브 직접 현금 판매 · 탐색 즉시 완료권 남발 · 죽은 스캐브 현금 부활 · **PC 본편 배송량 현금 판매** · 현질 전용 강력 장비

> 과금은 "불편함을 의도적으로 만든 뒤 제거하는 방식"이 아니라 **운영 편의성과 꾸미기** 중심.

## 15. MVP 범위

초기 MVP 에서 모든 시스템을 구현하지 않는다. **아래 루프가 재미있는지를 먼저 검증한다.**

### 필수 화면 4개

1. **홈** — NPC 일일 의뢰 / 공장 완료 알림 / 탐색 완료 알림
2. **공장** — 클리커 작업 1종 / 기본 생산 / 간단한 제작
3. **탐색** — 지역 4개 / 스캐브 파견 / 시간 경과 / 결과 처리
4. **창고** — 판매 / 납품 / 스캐브 장비 / 본편 발송 테스트

### 콘텐츠 규모

| 항목 | MVP 수량 |
|---|---|
| NPC | 1명 (`HWANG`) |
| 스캐브 | 3~5명 |
| 지역 | 4개 (`MYEONGDONG` `YONGSAN_MARKET` `GURO_FACTORY` `UIJEONGBU`) |
| 아이템 | 20~30개 |
| 공장 작업 | 1종 |
| 일일 의뢰 | 5~8개 풀 |

### MVP 제외

시즌 패스 · PvP · 플레이어 간 거래 · 길드 · 실시간 멀티플레이 · 대규모 스캐브 AI · 복잡한 애니메이션 · 수십 개 지역 · 복잡한 총기 제작 · 과도한 랜덤 뽑기 · 복잡한 서버 백엔드

## 18. 핵심 디자인 원칙

1. 모바일 게임만 플레이해도 완전한 게임이어야 한다
2. PC 본편 연동은 보너스이지 필수 조건이 아니다
3. 모바일 과금이 PC 본편 밸런스를 파괴해서는 안 된다

6. 일일 의뢰는 기존 콘텐츠를 다시 플레이하게 만드는 장치다
7. UI 는 모바일 게임보다 세계관 속 현장 단말기처럼 느껴져야 한다
8. 1인 개발이 가능한 범위를 우선한다
9. 불필요한 시스템은 추가하지 않는다
10. 본편의 자산과 세계관을 최대한 효율적으로 재활용한다
