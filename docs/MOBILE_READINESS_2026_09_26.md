# 모바일 안정성과 캐릭터 성장 작업

2026-09-26 진행도 점검 후 구현한 첫 개선 묶음이다. 초기 점검 기준은 커밋 `15977ce`이며, 최초 점검 내용은 [진행도 보고서](PROGRESS_REVIEW_2026_09_26.md)에 보존했다.

## 캐릭터 레벨

직접 탐색에서 살아 돌아오거나 의뢰를 완료하면 캐릭터 경험치를 받는다. 기존 기지 경험치와 별개로 저장되며, 파견·공장 중심의 기지 성장도 유지된다.

| 행동 | 캐릭터 경험치 |
|---|---:|
| 직접 탐색 생존 귀환 | 50 + 방문한 지점마다 10 |
| 첫 탐색 의뢰 보고 | 100 |
| 지역 정찰 의뢰 보고 | 75 |
| 지역 후속 의뢰 1차 / 2차 보고 | 100 / 150 |
| 일일 납품 | 해당 의뢰 데이터의 경험치 보상 |
| 사망·긴급 구조 | 생존 경험치 없음 |

누적 경험치 200에서 레벨 2가 된다. 기본 상한은 20이며 곡선과 보상은 [balance.json](../Assets/StreamingAssets/Data/balance.json)의 `characterProgression`에서 조정한다. 첫 용산 생존과 첫 의뢰 보고로 레벨 2에 도달할 수 있다.

캐릭터 프로필에 경험치 진행 막대와 다음 레벨까지 남은 양을 표시한다. 귀환 결과에는 획득 경험치와 레벨 상승을, 의뢰 목록에는 받게 될 경험치를 표시한다. 알림은 저장 성공 뒤에만 나온다. 완료된 탐색·의뢰를 다시 처리해도 보상을 중복 지급하지 않으며, 저장 실패 시 경험치·레벨·아이템·완료 상태를 함께 되돌린다.

기존 세이브의 캐릭터 경험치를 읽어 레벨을 동기화하고 기존 레벨을 낮추지 않는다. 과거에 이미 수령한 의뢰를 다시 지급하지 않는다. 이번 레벨은 성장 기록이며 전투 능력치나 지역 해금 보너스는 추가하지 않았다.

## 저장과 모바일 조작

- 정상 주 파일을 우선하고, 주 파일이 없거나 손상되면 정상 백업으로 복원한다.
- 복원 전 손상 파일은 이름을 달리해 보존한다. 두 사본 모두 읽을 수 없을 때 자동으로 새 게임을 만들지 않는다.
- 복구 화면에서 재시도 또는 명시적인 새 게임 시작을 선택할 수 있다. 새 게임은 두 번의 확인을 거친다.
- 권한·저장 공간 오류와 잘못된 저장 내용을 구분한다. 미래 버전의 주 파일을 오래된 백업으로 덮어쓰지 않는다.
- 전체 화면 팝업에 안전영역을 적용하고, 이미 안전영역 안에 있는 팝업에는 중복 적용하지 않는다.
- 뒤로 가기는 가장 위의 팝업부터 처리한다. 확인이 필요한 화면은 뒤의 UI로 입력을 전달하지 않는다.
- 앱 전환 시 누르고 있던 공장 입력을 해제하고, 복귀 직후 긴 프레임이 미니게임 결과를 즉시 결정하지 않게 한다.

## 성장 안내와 데이터 검사

잠긴 명동을 권하던 안내를 실제로 열려 있고 출발할 수 있는 지역·대기 인원·비용에 맞췄다. 고용주 3명 모두 안내가 제시한 일반 파견을 실제로 생성하는 검증을 추가했다.

지역 순서 검사는 현재 생환 경로를 사용한다. 탄약 한 발과 묶음 가격을 혼동한 검사를 바로잡고, 사고 손실과 위험 차이도 비교에 반영했다. 명동 전리품 횟수를 3~5회에서 6~8회로 조정한 근거와 300개 시드 비교는 [지역 보상 보정 기록](GROWTH_BALANCE_2026_09_26.md)에 정리했다.

- Unity EditMode 전체 670개 통과, 실패 0개.
- 고용주별 성장 흐름 standalone 검사 51개 통과.
- Python 지역 검사 회귀 테스트 4개 및 전체 데이터 검사 통과.
- 5개 언어 리소스 검사 23,609개 통과.
- 캐릭터 프로필·레벨 상승 결과·저장 복구 화면을 실제 Unity UI와 별도 메모리 세이브로 확인했다. 사용자의 진행 파일은 열지 않았다.

테스트 기록: `Logs/mobile-readiness-final.xml`. 화면 확인: `Logs/mobile-readiness-preview/`.

Android 개발 APK 생성 및 서명 검증도 완료했다. 원본 프로젝트의 `Builds/Android/AfterSeoul-mobile-readiness-20260926.apk`에 보관했다. 193,043,996바이트(약 184.1 MiB), ARM64, 최소 Android API 26이다. 빌드 오류 0개, 경고 2개이며 Unity 서비스 미연결과 테스트 메타데이터 갱신 경고가 남아 있다.

APK 소스는 `83c793579e85ce17f38146a0f3b6b6a391a6e8eb`이다. 같은 폴더의 `AfterSeoul-mobile-readiness-20260926.build.json`에 SHA-256, 버전, 빌드 결과를 기록했다. 패키지 ID와 서명은 기존 개발용 설정이며 스토어 배포본이 아니다.

첫 패키징 시 Java 내부 소켓 연결 오류가 발생했다. 이 컴퓨터의 빌드 프로세스에 한해 `TEMP`와 `TMP`를 짧은 Windows 경로 `D:\devSource\AfterSeoul\Logs\java-tmp`로 지정한 뒤 Gradle 초기화와 APK 생성이 통과했다. 컴퓨터의 전역 환경변수는 변경하지 않았다. 연결된 Android 기기가 없어 실기기 실행 검증은 남아 있다.

외부 베타 전에는 Android 실기기의 터치·뒤로 가기·안전영역·백그라운드 복귀, 발열·메모리·프레임과 실제 플레이 난이도를 확인해야 한다. 장기 경제와 복귀 동기는 자동 시뮬레이션만으로 확정하지 않았다. PC 연동 서비스, 실제 결제·광고, 출시 서명·패키지 설정은 후속 작업이다. 앱 실행 중 일반 저장 I/O 오류의 공통 재시도 안내도 부팅 복구와 별도로 보완할 여지가 있다.
